// the platform

Everything between source and sink

Six primitives that cover the full lifecycle of a data pipeline: from the moment a row is written to the moment it's queried.

Streaming ingestion

Connect Kafka, CDC streams, webhooks, or files. Inferreach handles backpressure and exactly-once delivery so nothing is dropped or duplicated.

SQL & Python transforms

Write transformations as version-controlled models. Inferreach resolves the dependency graph and runs only what changed.

DAG orchestration

Schedule, retry, and backfill with a scheduler that understands data dependencies, not just cron times.

Schema registry

Every table and topic carries a contract. Breaking changes are caught and blocked before they reach downstream consumers.

Lineage & observability

Trace any value back to its source in one click. Freshness, volume, and distribution are monitored on every table automatically.

Governance & access

Column-level masking, row-level policies, and full audit trails — enforced consistently across every pipeline and warehouse.

// how it's built

One DAG, every stage

A pipeline is declared once, as code. Inferreach compiles it into a directed graph and runs each stage independently, so a slow transform never blocks a healthy one.

  1. 01

    Declare sources

    Point at a database, topic, or bucket. Inferreach infers the initial schema and starts tracking drift.

  2. 02

    Define transforms

    Model the shape you want downstream in SQL or Python. Tests run on every commit, not just on deploy.

  3. 03

    Set delivery guarantees

    Choose exactly-once or at-least-once per sink, with configurable checkpointing and replay windows.

  4. 04

    Ship & observe

    Deploy triggers a canary run against sampled traffic. Full lineage and metrics are live from the first row.

orders_pipeline.yml 
name: orders-events-v2
source:
  type: kafka
  topic: orders.raw
  format: avro

transform:
  engine: sql
  model: models/orders_clean.sql
  tests: [not_null, unique_id]

sinks:
  - type: warehouse
    target: snowflake.analytics.orders
  - type: lake
    target: s3://lake/orders/

delivery: exactly_once
schedule: continuous
